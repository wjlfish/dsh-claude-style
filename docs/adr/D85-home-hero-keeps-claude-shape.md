# D85. 首屏保持 Claude 的版式，使用情况收进左下角卡片

## 背景

工作台式首页（`studio`）在新会话页中间放一块用量面板：六格数字、热力格与模型图。这套信息在 Claude Code Desktop 的新会话页上没有对应物，那一页只承载问候语、输入卡片与上下文行；面板把首屏从"开始对话"变成"看报表"。用量本身仍然值得看，但它是读者主动查看的东西。

## 决定

- `homeLayout` 的默认值改为 `classic`：首屏按 Claude 的版式画，品牌标与问候语居中，输入卡片在其下，上下文行贴着卡片底边；`studio` 仍保留为可选版面，`off` 仍是交给宿主原样。
- 使用情况进左侧个人信息菜单：账户卡片里多一个「使用情况」行（统计图标 + 标题），选中后关闭菜单，并在整个外壳上弹出一张对话框——里面就是原来首屏的「经典」用量面板：概览/模型两个页签、全部/30 天/7 天三段范围、六格数字、方格的活跃热力图和书籍换算那一句（`features/home/home-usage-dialog.ts`，样式复用 `home-overview.css` / `home-models.css`）。
- 对话框不改变菜单自身的高度与位置：菜单在指针下生长会触发宿主/自绘层的重新定位，那正是行在指针下跳动、菜单从指针下溜走的原因；对话框独立于菜单挂在 body 上，点遮罩、点关闭或 Esc 关闭。
- 这一行由账户区统一放进两种账户表面：宿主自带账户菜单时插进它注入到菜单列表头部的容器，宿主没有账户区时（Web）放进皮肤自绘的抽屉；打开卡片时按需读取 roll-up，关闭后不再订阅。
- 帐户行与工作台面板读同一个 roll-up 存储（经 homeLayout 句柄的 `usage` 与 `usageRows()`），因此两个入口的数字不会分叉；`classic` 下没有面板，读取只发生在这行被展开时。

## 后果

- 首屏回到"问候语 + 输入框"；用量在读者自己的账户卡片里，一次展开就能看到，不占页面也不另立入口。
- `studio` 版面与它的面板继续可用，选择该版面的读者行为不变；只是不再是默认。
- 账户区多一行，两种账户表面共用同一行实现；宿主菜单由宿主卸载，行随容器一起重建并重新插入，卡片随菜单关闭。
- `classic` 下打开这一行时才会读取 roll-up（`studio` 的常驻面板仍按自己的节奏刷新）；不打开就不读。

## 重审条件

- 宿主给账户菜单提供一个稳定的追加行槽位时，这一行改挂槽位，取消容器注入与重插。
- Claude 的新会话页形态再次变化（例如去掉上下文行或引入建议列表）时，按新的版式重画 `classic`，并重审本决策。
